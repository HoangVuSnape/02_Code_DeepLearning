0 Workflow tổng thể

Từ ảnh + câu hỏi y khoa → phân loại thành 1 answer trong từ điển đáp án của train, đo bằng exact-match để so sánh với Gemma cũ.

Hàm: src/data/vqa_rad.py → is_closed(). Chuẩn hóa normalize_answer(): lowercase → gộp khoảng trắng → bỏ dấu chấm cuối.

Chia train / validation — image-disjoint

  • 1 ảnh có thể có nhiều câu hỏi → nếu chia ngẫu nhiên theo dòng sẽ rò rỉ (leakage) cùng ảnh sang cả 2 phía.
  • image_key() = MD5 của bytes ảnh RGB → gom câu hỏi cùng ảnh; group_split(val_ratio=0.1, seed=42) đảm bảo cùng ảnh chỉ nằm một phía.
  • Tỉ lệ: 90% train / 10% val, deterministic theo seed → train.py và eval.py dựng lại giống hệt.

Answer vocabulary — biến VQA thành classification

  • build_answer_vocab(): lấy mọi answer duy nhất trong train split (đã normalize), sắp theo tần suất giảm dần rồi alphabet → {answer: class_id}. Số lớp C = số answer duy nhất.
  • Answer của test không có trong vocab → gán label = −1 → không bao giờ match → tính là sai trong EM (đúng protocol so với generation). % unseen được in ra làm trần của phương pháp (đưa vào limitations).
Vì sao classification mà so được với Gemma (generation)? Cả hai cùng chấm exact-match trên answer string đã normalize. Cùng thước đo → bảng so sánh hợp lệ, tách Closed/Open.

Vòng lặp 1 epoch

  1. Train: forward batch → CE loss → backward → AdamW step. Có tqdm (src/utils/progress.py).
  2. Val: forward không grad → tính loss + EM (overall/closed/open).
  3. Ghi history: train_loss, train_em, val_loss, val_em, val_em_closed, val_em_open, epoch_sec.
  4. Callbacks: on_epoch_end (Comet log) · nếu val_em cải thiện → lưu {name}_best.pt · nếu không cải thiện ≥ patience → dừng.
  5. Cuối run: ghi {name}_history.csv; on_run_end (Discord tóm tắt + push HF).

EM khi train/val (nội bộ, theo class id)

correct = (preds == labels) & (labels >= 0)   # unseen (-1) luôn sai
em_overall / em_closed / em_open  = tỉ lệ đúng trên từng nhóm

Trả về: best_val_em, params_total, params_trainable, checkpoint, history.

7 Train — RL (REINFORCE self-critical, nhóm D)

Chạy sau SFT, chỉ trên checkpoint tốt nhất. File: src/train/rl.py. Tối ưu trực tiếp reward không khả vi (EM, token-F1).

Reward mỗi mẫu — answer_reward()
r = 0.5·EM + 0.5·token_F1 giữa answer dự đoán và answer đúng (string). Label −1 (unseen) → reward 0.
Self-critical baseline — scst_epoch()
Sample answer từ Categorical(logits) và greedy = argmax. advantage = r(sample) − r(greedy). Loss = −(logπ(sample) · advantage).mean(). Grad clip 1.0. → giảm variance, không cần value network.
Vòng fine-tune — scst_finetune()
epochs = rl_epochs (5, smoke 1), lr = rl_lr (1e-5). Mỗi epoch đánh giá val EM, giữ checkpoint EM cao nhất. Có thể ra kết quả âm tính (REINFORCE variance cao) — vẫn là finding hợp lệ, giữ SFT làm final.
Thứ tự bắt buộc: SFT trước → RL sau. RL cần --load_checkpoint runs/<best>_best.pt và lặp lại đúng cờ kiến trúc của checkpoint đó.

Inference — predict_answers()

  1. Forward test batch → logits [B,C].
  2. Mặc định: pred = argmax(logits) → map class id → answer string qua id2answer.
  3. Constrained closed (nếu bật): câu closed thay bằng masked_closed_argmax (chỉ yes/no); câu open giữ argmax.
  4. Trả về hyps (list answer string) + p_yes (xác suất lớp yes, cho AUC).

Chấm điểm test — eval.py

# chế độ 1: đánh giá checkpoint (cờ PHẢI trùng train)
python eval.py --checkpoint runs/A8_111_best.pt \
  --image_attention --text_attention --decoder_attention \
  --save_metrics runs/A8_111_metrics.json \
  --save_predictions runs/A8_111_preds.csv [--constrained_closed]

# chế độ 2: chấm lại CSV Gemma (answer_ref, answer_pred) — không cần checkpoint
python eval.py --predictions_csv gemma_preds/gemma2b_test.csv \
  --save_metrics runs/gemma-2b-lora_metrics.json

eval.py cũng đo params_total/trainable và inference_time_sec. Xuất được prediction ra CSV để soi lỗi định tính.
