1 Tổng quan & Closed vs Open

Mọi câu trả lời (của model hoặc baseline) được chuẩn hoá normalize_answer() (lowercase → gộp khoảng trắng → bỏ dấu chấm cuối) rồi mới chấm. Câu hỏi chia 2 loại, đo riêng:

LoạiĐiều kiệnVí dụChỉ số chính
Closedanswer ∈ {yes, no}yes, noEM closed + Sens/Spec/Balanced-Acc/AUC
Opencòn lại (tự do)right lung, pneumonia, 2 cm…EM open, token-F1, Semantic

Vì sao tách? Câu closed chỉ có yes/no → đo như bài toán phân loại nhị phân y tế. Câu open là chuỗi tự do → cần nhiều thước đo mềm hơn EM.

2 Exact Match — EM chính

Logic Code: Được cài đặt bằng Python thuần (Pure Python). Hàm normalize_answer(s) thực hiện: chuyển chữ thường (lowercase) → loại bỏ các ký tự đặc biệt, dấu câu cuối câu → chuẩn hóa khoảng trắng thừa. Sau đó, so sánh bằng toán tử == giữa chuỗi tham chiếu (ref) và chuỗi dự đoán (pred).

em = sum(normalize_answer(ref) == normalize_answer(pred)) / N
Ví dụ: ref "yes" · pred "yes" → 1.   ref "right lung" · pred "left lung" → 0.   ref "pleural effusion" · pred "effusion" → 0 (thiếu 1 chữ là trượt).
Hạn chế: với câu open, EM quá khắt khe — model đúng gần hết vẫn bị 0. Trong kết quả, em_open gần như bằng 0 ở mọi model → dùng để so sánh closed thì tốt, nhưng open nên nhìn token-F1 / Semantic bên dưới.

3 Token-F1 (SQuAD-style)

Logic Code: Được cài đặt bằng Python thuần theo phong cách đánh giá của tập dữ liệu SQuAD. Đo mức độ trùng khớp cấp từ (token-level). Cả ref và pred sau khi chuẩn hóa sẽ được tách từ bằng hàm .split() để tạo thành tập hợp các từ (bag of words). Từ đó tính Precision, Recall và F1 score.

P = |trùng| / |pred| ;   R = |trùng| / |ref| ;   F1 = 2·P·R / (P+R)
Ví dụ: ref "left upper lobe" (3 token) · pred "left lobe" (2 token) → trùng 2 (left,lobe). P = 2/2 = 1.0, R = 2/3 ≈ 0.67 → F1 ≈ 0.80.

Với câu open, token_f1_open là thước đo bề mặt tốt hơn EM (thấy được model "đúng một phần"). Nhưng vẫn không hiểu đồng nghĩa (xem Semantic).

4 BLEU-1 phụ

Logic Code: Cài đặt thủ công bằng Python thuần để tránh phụ thuộc vào thư viện nltk. Tính toán Unigram Precision (độ khớp của các từ đơn) kết hợp với phạt độ dài (Brevity Penalty - BP) để tránh việc mô hình sinh câu quá ngắn nhằm đạt điểm Precision cao.

BLEU-1 = BP × (số token pred trùng ref, có clip) / |pred|
Ví dụ: ref "right lung" · pred "lung" → precision 1/1 nhưng pred ngắn hơn → BP phạt → < 1.
Lưu ý: câu trả lời VQA-RAD rất ngắn (1–3 từ) nên BLEU-1 gần như trùng thông tin với token-F1 và khá nhiễu. Giữ làm phụ, không dùng làm chỉ số chính.

5 Semantic Similarity MỚI

Logic Code: Sử dụng thư viện sentence-transformers trong Python. Tải mô hình nhúng câu pre-trained all-MiniLM-L6-v2 thông qua lớp SentenceTransformer.

Quy trình tính toán từng mẫu trong code như sau:

  1. Lấy vector nhúng cho ref và pred bằng hàm:
    model.encode(..., convert_to_numpy=True, normalize_embeddings=True).
    Việc bật normalize_embeddings=True giúp các vector đầu ra có độ dài L2 bằng 1.
  2. Do vector đã chuẩn hóa, độ tương đồng Cosine (Cosine Similarity) được tính đơn giản bằng tích vô hướng (dot product) giữa hai vector:
    cosine_sim = (r_vector * h_vector).sum(axis=-1).
  3. Điểm sem_open tổng thể là trung bình cộng Cosine Similarity của toàn bộ các câu hỏi mở.
sem = trung bình cosine( emb(ref), emb(pred) )   ∈ [~0, 1]
Ví dụ: ref "pneumonia" · pred "infection" → EM = 0, token-F1 = 0, nhưng semantic ≈ 0.6–0.7 (gần nghĩa).   ref "left lung" · pred "lung on the left" → semantic ≈ 0.9.
Vì sao thêm: EM-open bằng 0 ở mọi model → che mất khác biệt. Semantic cho điểm phần theo nghĩa → các model tách hạng rõ ràng, đúng chuẩn đánh giá sinh chữ hiện đại. Chỉ tính lúc eval (không tính trong vòng train để khỏi tải model mỗi epoch). Nếu không cài sentence-transformers hoặc tải model lỗi → sem_open = null, không làm hỏng pipeline.

6 Chỉ số lâm sàng — subset yes/no

Thư viện sử dụng: Được tính toán thông qua các hàm trong thư viện học máy scikit-learn (cụ thể là gói sklearn.metrics).

Logic Code: Coi nhãn "yes" là lớp dương tính (1), nhãn "no" là lớp âm tính (0). Dựa vào xác suất dự đoán p_yes của mô hình:

  1. Áp dụng ngưỡng mặc định 0.5 trên p_yes để phân loại nhị phân ra nhãn dự đoán (1 hoặc 0).
  2. Sử dụng hàm confusion_matrix(y_true, y_pred) để tính ra các giá trị: True Positives (TP), False Negatives (FN), True Negatives (TN), False Positives (FP).
  3. Từ ma trận nhầm lẫn này, tính toán các chỉ số lâm sàng truyền thống.
Chỉ sốCông thứcÝ nghĩa
clin_sensitivityTP / (TP+FN)Bắt đúng bao nhiêu ca "yes" (recall lớp yes)
clin_specificityTN / (TN+FP)Bắt đúng bao nhiêu ca "no"
clin_precisionTP / (TP+FP)Trong các lần đoán "yes", đúng bao nhiêu
clin_balanced_acc MỚI(Sens + Spec) / 21 số cân bằng khi yes/no lệch — dễ so sánh
clin_f1 MỚI2·P·R / (P+R)Hài hoà precision & recall lớp yes
clin_aucROC-AUC (sklearn)Phân biệt yes/no ở mọi ngưỡng; 0.5 = ngẫu nhiên
Ví dụ: 4 câu yes/no, thật = [yes, yes, no, no], đoán = [yes, no, no, yes] → Sens = 1/2 = 0.5, Spec = 1/2 = 0.5 → Balanced-Acc = 0.5.
Khuyến nghị: đưa clin_balanced_acc vào bảng chính thay vì 3 cột sens/spec/precision rời rạc; giữ clin_auc làm chỉ số bổ trợ.

7 p_yes tính thế nào (nền của AUC)

Logic Code: Để tính được ROC-AUC (clin_auc) không phụ thuộc vào ngưỡng cố định, ta cần xác suất liên tục của lớp "yes". Trong mã nguồn, xác suất này được thu thập như sau:

  • Mô hình phân loại MLP (Nhóm A & P_pubmed_mlp): Lấy trực tiếp từ giá trị đầu ra của lớp phân loại nhị phân sau khi đi qua hàm kích hoạt softmax.
  • Mô hình sinh chữ (GPT-2 và Gemma LoRA): Lấy giá trị logit (xác suất chưa chuẩn hóa) của token đầu tiên được sinh ra, chỉ xét trên hai token đại diện cho đáp án đóng là "yes" và "no", sau đó áp dụng hàm softmax trên cặp này:
    p_yes = exp(logit_yes) / (exp(logit_yes) + exp(logit_no)).
  • Từ tệp dự đoán CSV (G Gemma raw không có logits): Do chỉ có chuỗi văn bản đầu ra, xác suất được quy đổi thô: nếu câu sinh chứa từ "yes" → 1.0, nếu chứa "no" → 0.0, các trường hợp khác gán 0.5.

8 Chi phí (trade-off)

Logic Code:

  • params_total và params_trainable được tính bằng cách đếm số lượng phần tử tensor trong mô hình PyTorch:
    • Tổng tham số: sum(p.numel() for p in model.parameters())
    • Tham số học được: sum(p.numel() for p in model.parameters() if p.requires_grad)
  • inference_time_sec: Đo bằng thư viện time bằng cách tính khoảng thời gian chênh lệch trước và sau khi thực hiện vòng lặp dự đoán trên tập test (đơn vị giây).

10 Đọc kết quả sao cho đúng

  • Câu closed → dùng em_closed + clin_balanced_acc (và clin_auc).
  • Câu open → đừng chỉ nhìn em_open (là floor, gần 0). Nhìn token_f1_open và sem_open để thấy khác biệt thật.
  • Trade-off → so bằng params_trainable, không phải params_total.
  • Run smoke_* (1 epoch) là degenerate (đoán toàn yes) → đã tự loại khỏi bảng in trong report.py.
