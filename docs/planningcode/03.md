# nghiên cứu thực nghiệm với số lượng model nào, cần làm gì, viết ra kế hoạch check list để mình kiểm soát đi

Với Kaggle/Colab Free, bạn nên làm **5 model thí nghiệm chính**, không hơn. Thiết kế này đủ để trả lời câu hỏi “attention đặt ở đâu hiệu quả nhất?” mà vẫn kiểm soát được compute; kế hoạch thực nghiệm tốt cần xác định rõ biến đầu vào, metric đầu ra và giữ các điều kiện còn lại cố định.[^1]

## Phạm vi chốt

**Tên hướng nghiên cứu:**
**Ablation Study of Attention Placement in a Lightweight CNN–BiLSTM–Decoder for Medical Multimodal Classification**

**Bài toán:**
Ảnh X-ray/ảnh y tế + clinical text ngắn → dự đoán `Normal` hoặc `Abnormal`.

**Không làm trong scope chính:**

- Không train Transformer/ViT/LLM lớn từ đầu.
- Không làm multi-label phức tạp ngay từ đầu.
- Không train RL/PPO/RLHF thật.
- Không thử quá nhiều fusion method.
- Không chạy toàn bộ 8 tổ hợp attention.


## Số lượng model

### Bắt buộc: 5 model

| ID | Model | CNN attn | LSTM attn | Decoder attn | Mục đích |
| :-- | :-- | :--: | :--: | :--: | :-- |
| M0 | Baseline | No | No | No | Mốc gốc để so sánh |
| M1 | CNN-Attention | Yes | No | No | Kiểm tra attention ở ảnh |
| M2 | LSTM-Attention | No | Yes | No | Kiểm tra attention ở text |
| M3 | Decoder-Attention | No | No | Yes | Kiểm tra attention sau fusion |
| M4 | Full-Attention | Yes | Yes | Yes | Kiểm tra kết hợp cả ba [^2] |

Đây là **5 model architecture**, nhưng nếu chạy 3 seed thì thành **15 lần train**. Để phù hợp quota, chạy một seed ở vòng sàng lọc; chỉ chạy lại top-2 model bằng 3 seed nếu còn GPU.

### Tùy chọn: 1 baseline mở rộng

Chỉ thêm khi bạn đã chạy xong 5 model trên:


| ID | Model | Mục đích |
| :-- | :-- | :-- |
| M5 | ResNet-18 pretrained + BiLSTM + Decoder | Kiểm tra CNN tự viết có thua backbone pretrained nhẹ hay không |

Không nên thêm M5 nếu deadline gấp. Bài vẫn hoàn chỉnh với M0–M4.

## Thiết kế kiểm soát

### Biến thay đổi

Chỉ thay đổi **vị trí attention**:

$$
A = (A_{cnn}, A_{lstm}, A_{decoder})
$$

Ví dụ:

- M0: $(0, 0, 0)$
- M1: $(1, 0, 0)$
- M2: $(0, 1, 0)$
- M3: $(0, 0, 1)$
- M4: $(1, 1, 1)$


### Biến phải cố định

Checklist này rất quan trọng; nếu thay đổi nhiều thứ cùng lúc thì không kết luận được attention tạo ra khác biệt hay không.[^1]

- [ ] Cùng dataset và cùng file split train/validation/test
- [ ] Cùng số mẫu của mỗi lớp
- [ ] Cùng preprocessing ảnh
- [ ] Cùng template/text preprocessing
- [ ] Cùng vocabulary, `MAX_LEN`, embedding dimension
- [ ] Cùng custom CNN/BiLSTM/decoder dimensions
- [ ] Cùng batch size
- [ ] Cùng số epoch tối đa
- [ ] Cùng optimizer AdamW
- [ ] Cùng learning rate
- [ ] Cùng loss function và class weights
- [ ] Cùng early-stopping condition
- [ ] Cùng random seed khi chạy vòng 1
- [ ] Cùng metric và test protocol


## Checklist tổng thể

### Phase 0: Chốt đề bài

- [ ] Chốt bài toán binary classification: `Normal` vs `Abnormal`
- [ ] Viết mục tiêu nghiên cứu: đánh giá tác động attention ở CNN, BiLSTM, decoder
- [ ] Viết 3 câu hỏi nghiên cứu
- [ ] Chốt metric chính là **macro-F1** hoặc **ROC-AUC**
- [ ] Chốt metric phụ: accuracy, recall, precision, specificity, params, training time
- [ ] Tạo GitHub repository hoặc Kaggle Dataset/Notebook version để lưu code
- [ ] Tạo Google Drive để backup checkpoint, CSV metric và hình kết quả


### Phase 1: Chuẩn bị data

- [ ] Chọn dataset ảnh y tế có nhãn rõ ràng
- [ ] Kiểm tra license và điều kiện dùng dataset
- [ ] Kiểm tra số lượng ảnh mỗi class
- [ ] Loại file hỏng, ảnh lỗi hoặc duplicate rõ ràng
- [ ] Kiểm tra có patient ID không
- [ ] Nếu có patient ID: split theo patient, không split theo ảnh
- [ ] Tạo `train.csv`, `val.csv`, `test.csv`
- [ ] Cố định seed khi tạo split
- [ ] Kiểm tra không trùng image ID giữa train/val/test
- [ ] Kiểm tra tỷ lệ class ở ba tập gần tương đương
- [ ] Xác định text lấy từ đâu: report thật, metadata, hay template không leakage
- [ ] Kiểm tra text không có từ tiết lộ trực tiếp nhãn
- [ ] Chụp/lưu bảng thống kê dữ liệu để đưa vào báo cáo


### Phase 2: Preprocessing

- [ ] Chọn kích thước ảnh: 128 x 128 cho CNN nhỏ
- [ ] Xác định normalize image
- [ ] Chỉ dùng augmentation trên train
- [ ] Dùng augmentation nhẹ, tránh biến đổi phá hủy dấu hiệu bệnh
- [ ] Lowercase và tokenize text
- [ ] Xây vocabulary chỉ từ train set
- [ ] Đặt `PAD_ID = 0`
- [ ] Chọn `MAX_LEN = 32` hoặc 48
- [ ] Kiểm tra tỷ lệ câu bị truncate
- [ ] Lưu vocabulary thành JSON/Pickle
- [ ] Kiểm tra dataloader bằng một batch thật
- [ ] In shape: image, tokens, label
- [ ] Visualize ngẫu nhiên 8–16 sample để kiểm tra label và text đúng ảnh


### Phase 3: Implement model

- [ ] Viết `ImageEncoder` với CNN nhỏ
- [ ] Viết `ChannelAttention`/SE block cho CNN
- [ ] Viết `TextEncoderBiLSTM`
- [ ] Viết padding mask cho text
- [ ] Viết `TemporalAttention` cho hidden states của LSTM
- [ ] Viết fusion bằng concatenate
- [ ] Viết `GatedAttention` cho fused vector
- [ ] Viết `Decoder` MLP
- [ ] Viết `FusionModel` nhận ba cờ attention
- [ ] Kiểm tra forward pass không lỗi
- [ ] Kiểm tra output shape là `[batch_size, 2]`
- [ ] Kiểm tra loss backward chạy được
- [ ] In số lượng trainable parameters của từng model
- [ ] Chạy overfit test trên 32–64 samples; model phải overfit gần 100% train accuracy trước khi train thật


## Phase 4: Thiết lập training

- [ ] Chọn `BATCH_SIZE = 32`; giảm xuống 16 nếu hết VRAM
- [ ] Chọn `EPOCHS = 12`
- [ ] Chọn `LR = 1e-3`
- [ ] Chọn `WEIGHT_DECAY = 1e-4`
- [ ] Dùng `AdamW`
- [ ] Dùng `CrossEntropyLoss`
- [ ] Thêm class weights nếu data lệch lớp
- [ ] Bật mixed precision nếu có CUDA
- [ ] Dùng early stopping với `patience = 3`
- [ ] Monitor validation macro-F1 hoặc AUC
- [ ] Lưu `best.pt` theo validation metric
- [ ] Log theo từng epoch ra CSV
- [ ] Log GPU, thời gian/epoch, memory nếu đo được
- [ ] Lưu config thành `config.json`


## Phase 5: Pilot run

Chỉ chạy baseline M0 trước, không chạy cả năm model ngay.

- [ ] Chạy M0 với 10% dữ liệu, 2 epoch
- [ ] Check loss giảm
- [ ] Check validation metric hợp lý
- [ ] Check không có NaN/Inf
- [ ] Check GPU không OOM
- [ ] Check file checkpoint được lưu
- [ ] Check loss/accuracy CSV ghi đúng
- [ ] Check prediction không chỉ có một class
- [ ] Check confusion matrix không có lỗi label mapping
- [ ] Kiểm tra dấu hiệu data leakage
- [ ] Chỉ qua pilot mới chạy full dataset


## Phase 6: Thực nghiệm chính

Chạy tuần tự theo thứ tự dưới đây để hạn chế rủi ro mất quota:

- [ ] Run 01: M0 Baseline
- [ ] Lưu checkpoint, history CSV, config, runtime
- [ ] Run 02: M1 CNN attention only
- [ ] Lưu checkpoint, history CSV, config, runtime
- [ ] Run 03: M2 LSTM attention only
- [ ] Lưu checkpoint, history CSV, config, runtime
- [ ] Run 04: M3 Decoder attention only
- [ ] Lưu checkpoint, history CSV, config, runtime
- [ ] Run 05: M4 Full attention
- [ ] Lưu checkpoint, history CSV, config, runtime
- [ ] Đánh giá tất cả model bằng đúng test set một lần
- [ ] Không chỉnh hyperparameter sau khi đã xem test result

Một thiết kế thực nghiệm tốt hướng đến ít lần chạy nhưng nhiều thông tin; nếu số yếu tố và cấu hình tăng, số lần thí nghiệm tăng rất nhanh.[^1]

## Phase 7: Chạy lại top model

Sau 5 run chính:

- [ ] Chọn top-2 theo validation macro-F1, không chọn theo test
- [ ] Chạy lại mỗi model với seed `42`, `123`, `2026`
- [ ] Báo cáo mean và standard deviation
- [ ] Chọn final model dựa trên macro-F1/AUC và stability
- [ ] Nếu không đủ GPU: ghi rõ nghiên cứu chạy một seed do giới hạn compute

Mục tiêu thực tế:

- **Tối thiểu:** 5 runs, mỗi model 1 seed.
- **Tốt:** 5 runs + top-2 chạy 3 seed, tổng 9 runs.
- **Rất tốt nhưng không cần thiết:** toàn bộ 5 model × 3 seeds = 15 runs.


## Phase 8: Phân tích kết quả

- [ ] Tạo bảng metric test cho M0–M4
- [ ] Có accuracy, macro-F1, precision, recall, specificity, AUC
- [ ] Có params và training time
- [ ] Bôi đậm model tốt nhất theo metric chính
- [ ] Tính chênh lệch với baseline: `delta = score_case - score_baseline`
- [ ] Vẽ validation loss của 5 model
- [ ] Vẽ validation macro-F1 của 5 model
- [ ] Vẽ confusion matrix của best model
- [ ] Vẽ ROC curve cho top-2
- [ ] So sánh overfitting: train metric vs validation metric
- [ ] Kiểm tra full attention có thực sự tốt nhất hay overfit
- [ ] Phân tích “performance–cost trade-off”: metric tăng bao nhiêu so với thêm bao nhiêu params/thời gian

## Tiêu chí dừng

- **Dừng model** nếu validation metric không vượt baseline sau 5 epoch và loss không giảm.
- **Giảm batch size** nếu OOM.
- **Giảm image size từ 224 xuống 128** nếu runtime quá cao.
- **Không đổi kiến trúc giữa chừng** trong 5 run chính.
- **Không dùng test set để chọn hyperparameter**.
- **Không kết luận full attention tốt nhất** nếu chênh lệch nhỏ hơn dao động giữa seed hoặc đi kèm overfitting.
